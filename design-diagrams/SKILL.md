# design-diagrams

本技能是 `brainstorming` 的**内部出图能力**：把类型化 JSON IR 在本地确定性渲染成
可脱离环境打开的自包含 SVG，供设计文档以图片引用方式嵌入。它**不面向用户直接调用**，
由 `brainstorming` 在撰写设计文档的落盘阶段自动调用。

五类图：`architecture`（架构图）、`workflow`（工作流图）、`sequence`（时序图）、
`dataflow`（数据流图）、`lifecycle`（生命周期图）。**没有类图能力。**

---

## 1. 何时被调用（出图时机）

- 由 `brainstorming` 在**设计文档落盘阶段**调用出图。
- 图与文档**同批进变更清单门**：本次将新建 / 重渲染的图文件与文档改动一起列出、
  一并获批后才写盘；**不在变更清单之外单独落盘图**。
- 用户只继续用自然语言聊架构逻辑；**不手写 IR，也不需要知道 schema 存在**。

## 2. 内部技能边界与拒绝话术

- 本技能声明为**内部技能**：可以被 `brainstorming` 调用，
  **不得**因用户直接提出的画图请求而被自动选中。
- 遇到用户**直接**要求画图（对话不在 `brainstorming` 的设计流程 / 设计文档落盘阶段）时，
  **不接管**该请求，说明：本技能由 `brainstorming` 在设计文档产出时调用；
  出图需要设计文档的对应节先有内容，请回到 `brainstorming` 的设计与落盘流程，
  或说明要出图的是哪份设计文档的哪一节。

## 3. 调用方式与出图入口

- `brainstorming` 用 **Skill 工具**调用本技能，传入三样：**图类型、IR、目标路径**；
  本技能产出 SVG 后返回**校验结果与产物路径**。
- 出图入口（子命令 `svg`）：

  ```bash
  node <本技能目录>/bin/design-diagrams.mjs svg <type> <ir.json> <output.svg>
  ```

- 该入口的链路：**先校验** → 子进程渲染 → 从产物中提取 `<svg>` →
  组装自包含独立 SVG（内联字体 CSS、深浅两套主题变量、内联样式）→ **原子写**
  `<output.svg>`；同时把 IR 逐字节落盘为**同目录同名**的 `<output.json>`。
- 退出码：`0` 成功；`1` 校验或渲染失败；`2` 用法错误（未知图类型、路径冲突、
  输出路径覆盖输入 IR）；`3` 两轮降级停止（见第 7 节）。
- `<type>` 取值仅限 `architecture` / `workflow` / `sequence` / `dataflow` / `lifecycle`；
  传入其他取值时非 0 退出并列出合法取值，不产出任何文件。

## 4. IR 由谁产出、事实来源限定

- IR 由 **`brainstorming` 自己**依据该节**已有内容**生成，是一份符合对应 schema 的
  类型化 JSON；节点与连线的位置由渲染器计算，IR 不规划坐标。
- **事实来源限定为该节**：不得引入该节没有的组件、参与者、状态或关系。
  文档该节里没有的东西，不许出现在图里。

## 5. 图类型选型规则（按对象性质选，不按作者偏好）

| 要描述的对象性质 | 图类型 |
|---|---|
| 系统整体结构（组件、服务、数据库、云资源、安全边界） | `architecture` |
| 不同责任方或阶段的分工、含审批门与异常分支（泳道） | `workflow` |
| 谁调用谁、什么顺序、每步返回什么（API 调用链、缓存回源、鉴权检查） | `sequence` |
| 数据从哪来、经过哪些处理、存到哪去，或需要标出敏感数据边界 | `dataflow` |
| 状态迁移、重试、等待与终态 | `lifecycle` |

## 6. 产出路径、图名派生与共用图文件

- 图落 `<设计文档所在目录>/diagrams/<图名>.svg`；IR 与图**同目录同名**，
  仅扩展名不同（`.json`）。
- **图名派生规则**：输入流程名或章节语义名，保留字母、数字与 CJK 字符，其余字符
  替换为 `-`，连续 `-` 折叠为单个，去掉首尾 `-`，ASCII 部分小写化；结果为空则回落到
  图类型名。
- **冲突处理**：派生结果冲突时追加 `-2`、`-3` 依次递增，并**报出冲突双方**，
  **不静默改名**。
- **共用图文件**：同一流程名在架构总纲与模块文档中共用**同一个**图文件
  （同名流程两处图类型必须一致，共用一份既省体积又消除两份需同步的风险）。
- **md 引用形态**：设计文档用 `![<说明>](diagrams/<图名>.svg)` 引用该图；
  **正文不得出现 `<svg>` 标签**，不得把 SVG 内容内联进正文。

## 7. 校验硬门与两轮降级

- **校验硬门**：出图前必须通过几何校验（节点重叠、连线穿过无关节点、关系标签遮挡）。
  校验未通过**不产出 SVG**，且**不覆盖既有同名文件**（磁盘上不留半成品）。
- **目标错误数口径**：校验诊断中**错误级**条目的条数，**不含警告**。
- **两轮降级（基线轮计入两轮）**：第 1 轮诊断记为目标基线；第 2 轮错误数若
  **未低于**第 1 轮，立即停止自动修正（退出码 `3`）。第 2 轮若下降则继续，之后每轮
  与上一轮比较，**连续两轮之间未下降**即停。
- **停止后不代选**：向调用方报出**未解决项**（哪个图、哪条诊断、当前与历史错误数），
  并把「**保留占位继续落盘**」与「**继续修正**」两个选项交回用户，
  **不得代为选择**。
- **交回调用方用于清单标注**：停止后把该图连同其**状态（未通过校验）与原因
  （未解决的诊断项 / 错误数）**交回调用方，供其在变更清单中标注。

## 8. 环境不满足时的降级

- 运行环境没有满足版本要求的 Node（**最低 18**）时，**跳过出图**、在设计文档中
  **留占位并说明原因**，并在变更清单中**标注**该状态。
- 此降级**不阻塞文档落盘**。
